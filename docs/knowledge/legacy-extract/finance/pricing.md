## 1. 范围与证据强度

Legacy 的价格能力分散在产品、报价与 Finance 运营页，主要分为：

1. **产品基准价**：产品主数据保存成本价与销售价；
2. **报价行定价**：使用成本与目标销售毛利率反推单价，是实际报价链的一部分；
3. **独立价格计算器**：按成本加成、折扣、汇率计算结果，不保存定价决策；
4. **成本与多维价格规则表**：`product_costing`、`product_price_rules` 有结构但未接入完整业务；
5. **价格智能中心**：页面描述了利润监控、推荐等能力，但活动路由未提供所需数据，更多是壳层/路线图。

产品主数据中的成本价、销售价和客户历史报价只作为输入或建议。未观察到成熟的价格规则执行引擎、审批矩阵、价格表有效期或竞争价格库。

## 3. 流程

### 3.1 报价行定价

1. 用户选择产品并输入数量、成本和目标销售毛利率。
2. 若输入成本无效，则读取产品主成本。
3. 系统反推单价，计算单位利润和行金额。
4. 保存报价行并重算报价总额。
5. 报价详情展示客户历史价格统计供人工参考。
6. 批准前允许人工修改数量/单价；系统重新计算金额、利润及销售毛利率。
7. 人工确认后报价进入已发送状态；转销售订单是另一独立动作。

### 3.2 独立价格试算

1. 选择产品并输入总成本、目标加成率、折扣率和汇率。
2. 先按成本加成计算售价。
3. 再应用折扣得到最终价。
4. 按输入汇率换算 USD 价。
5. 仅展示结果，不形成价格版本或生效记录。

### 3.3 价格参考

1. 产品主数据提供成本价与销售价。
2. 客户最近报价提供历史单价提示。
3. 报价页面计算最近/最低/最高/平均值。
4. 用户决定最终价格；AI/历史记录不自动提交。

## 5. 数据含义

| Concept / Field | Legacy 含义 |
|-----------------|-------------|
| 产品 `cost_price` | 默认成本输入，不一定是带批次/日期的实际成本 |
| 产品 `sale_price` | 产品主数据参考售价 |
| 报价行 `cost_price` | 报价时采用的成本快照 |
| 报价行 `price` | 单位销售价 |
| 报价行 `qty` | 数量 |
| 报价行 `amount` | 数量乘单位销售价 |
| 报价行 `profit` | 单位销售价减单位成本 |
| 报价行 `profit_rate` | 报价链主要按销售毛利率解释；批准页按利润/售价重算 |
| 报价头 `total_amount` | 行金额合计 |
| 报价头 `gross_profit` | 总销售额减总成本 |
| `discount_rate` | 独立计算器的折扣百分比 |
| `exchange_rate` | 独立计算器/报价头汇率；Legacy 未统一说明方向 |
| 客户历史价格 | 最近报价行单价的参考，不是合同价格表 |
| `pricing_rules` | Finance 边界声明的共享表；未观察到可靠活动规则引擎 |
| `product_costing` | 产品成本分解与建议价结构；活动提交未持久化 |
| `product_price_rules` | 客户等级/国家/币种等多维价规则结构；未接入运行计算 |
| 样品 `target_price` | 客户或项目期望价，供后续报价参考 |

### 公式口径警告

| 场景 | 公式含义 |
|------|----------|
| 报价行目标毛利率 | 售价反推，使 `(售价 − 成本) / 售价` 达到目标 |
| 独立价格计算器 | 成本加成，使 `售价 = 成本 × (1 + 加成率)` |

相同的 `profit_rate` 名称承载了不同商业口径，迁移时必须拆分命名。
