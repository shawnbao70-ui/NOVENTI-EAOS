## 1. 范围与证据强度

本模块覆盖客户应收、收款、催收、供应商应付、付款及其状态汇总。

Legacy 同时存在两套客户应收口径：

- **经营汇总口径**：客户销售订单总额减该客户全部收款；
- **应收台账口径**：交付单经人工确认后写入 `ar_records`。

两者没有可观察到的自动对账机制，因此不能假设数值始终一致。应付链路较清晰：采购单生成采购发票时同步生成 `ap_records`；但付款登记只扣银行余额，未观察到对应 AP 的核销更新。

## 3. 流程

### 3.1 销售订单收款

1. 读取销售订单及既有收款合计。
2. 计算订单剩余余额。
3. 若无剩余，修正订单为 `Paid`，不新增收款。
4. 若有剩余，按全部余额新增一笔收款，默认银行转账、USD。
5. 重算订单累计已收与余额。
6. 余额为零则订单 `Paid`，否则 `Partial`。

### 3.2 交付记应收

1. 从交付单取得客户、来源单号、金额与明细预览。
2. 展示“应收计提、非税务发票”的确认页。
3. 提示是否已有同来源应收，以及交付是否尚未发运。
4. 人工确认后建立全额、余额等于金额、状态 `Unpaid` 的应收记录。
5. 进入 AR Dashboard；收款在独立流程处理。

### 3.3 催收提醒

1. 按客户经营应收计算未收余额。
2. 生成可编辑提醒草稿。
3. 余额为零时禁止批准。
4. 人工确认后登记 `Pending` 催收任务；不自动发信。
5. 主任务表不可用时尝试登记客户跟进。

### 3.4 采购开票与应付

1. 读取采购单。
2. 检查该采购单是否已有采购发票。
3. 生成采购发票，金额取采购单总额，初始 `Unpaid`。
4. 同时建立 AP，金额与余额均为发票全额、已付为零。
5. AP Dashboard 汇总未付、发票总额和已付总额。

### 3.5 付款登记

1. 人工选择供应商、银行账户、金额和付款方式。
2. 生成人工付款记录。
3. 从所选银行账户扣减金额。
4. **流程在此终止**：未观察到自动选择发票、分摊、核销或更新 AP。

## 5. 数据含义

### 5.1 主要实体

| Entity | 含义 |
|--------|------|
| `receipts` | 销售订单收款事实，关联客户和销售订单 |
| `sales_orders` 收款字段 | 订单级累计已收、剩余余额、付款状态 |
| `ar_records` | 由交付来源生成的应收子账记录 |
| `receivables` | 另一套带发票号、到期日的应收结构；未观察到主流程持续使用 |
| `collection_tasks` | 人工催收待办，不代表消息已发送 |
| `purchase_invoices` | 采购单对应的供应商发票头 |
| `ap_records` | 采购发票对应的应付子账 |
| `treasury_payment_records` | 对供应商的资金付款记录 |
| `treasury_bank_accounts` | 银行账户及当前余额 |

### 5.2 金额字段

| Field | 含义 |
|-------|------|
| `amount` | 原始应收/应付或本次收付款金额 |
| `received_amount` | 应收结构中的累计收款金额 |
| `paid_amount` | 采购发票/AP 中累计付款金额 |
| `balance` / `balance_amount` | 尚未收取或支付的余额 |
| `total_sales - total_received` | 客户经营应收口径，不是逐笔子账核销结果 |

### 5.3 状态语义

| Status | 使用位置 | 含义 |
|--------|----------|------|
| `Unpaid` | 新建 AR、采购发票、AP | 尚未收/付 |
| `Open` | `receivables` 默认及部分页面 | 尚未关闭 |
| `Partial` | 销售订单付款状态、页面兼容显示 | 部分收/付 |
| `Paid` | 销售订单及页面兼容显示 | 已结清 |
| `Closed` | AR Center 开放记录过滤 | 已关闭 |
| `Pending` | 催收任务 | 待人工跟进，不代表已发送 |
