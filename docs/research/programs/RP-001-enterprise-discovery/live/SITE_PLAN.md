# RP-001 Site Plan

**Program:** Enterprise Discovery  
**Status:** **Open** · **0 Complete**  
**Assigned observer/site/window:** none / none / none  
**Access basis:** [SITE_ACCESS_PACK](../../../templates/SITE_ACCESS_PACK.md) · **Evidence review:** [ARTIFACT_ACCEPTANCE_RUBRIC](../../../templates/ARTIFACT_ACCEPTANCE_RUBRIC.md)

## Objective and boundary

Observe whether a named cohort can produce a traceable Discovery Dossier through Sense → Structure → Score → Dossier → Advise. Observation is read-only/facilitated research; scores do not authorize decisions, permissions, grants, or product changes.

## Target observation points

1. Source intake distinguishes system facts, participant statements, assumptions, and unresolved conflicts.
2. Profile, DNA, Capability, Organization, AI/automation/infrastructure readiness, Knowledge, Growth Stage, Evolution Potential, and roadmap remain distinct.
3. Org≠Capability is preserved when participants use department language.
4. Scoring rationale traces to sources and records uncertainty rather than forcing a value.
5. Human-facilitated and AI-assisted steps expose provenance, review, and correction paths.
6. Time-to-dossier, participant burden, missing data, and exception density are measured.
7. Advice remains bounded to evidence and includes HOLD/no-recommendation where support is weak.
8. Restricted data is minimized and represented by controlled handles.

## Required artifacts

1. Dated agenda/session record and named cohort/site scope.
2. Authorized, redacted source inventory with owners and access classifications.
3. Completed discovery worksheets with instrument/version identifiers.
4. Versioned Discovery Dossier output.
5. Claim-to-source and domain-coverage trace matrix.
6. Scoring rationale, conflict, missing-data, and falsifier log.
7. Facilitation/AI-assistance audit and correction history.
8. Artifact manifest with integrity, provenance, retention, redaction, and custodian fields.

## Dependency systems / contexts

1. Enterprise profile/master-data source or approved extract.
2. Process/service/workflow documentation repository.
3. Capability and organization reference sources, kept logically separate.
4. Knowledge/document repository with source ownership metadata.
5. Readiness/infrastructure/automation evidence sources.
6. Controlled workshop and dossier-authoring environment.

## Access and run sequence

1. Approve cohort, systems, consent, recording, exports, and data-minimization plan.
2. Validate read-only access and artifact handles before the session.
3. Observe collection and scoring without operating source systems.
4. Reconcile artifacts, deviations, conflicts, and access revocation on exit.

## Risks / ethics

1. Confidential strategy or personal data over-collection; minimize and redact at source.
2. Facilitator confirmation bias or sponsor pressure; preserve dissent and falsifiers.
3. Department names collapsing into capabilities; invoke Org≠Capability stop/correction.
4. Discovery maturity used as employee/vendor judgment; prohibit secondary evaluative use.
5. AI-assisted notes leaking restricted data or obscuring provenance; use approved environment and explicit audit.
6. Advice treated as authorization; state non-claims in every handoff.

## Exit conditions

1. Stop if consent/access is missing, revoked, or scope expands beyond approval.
2. Stop if restricted data cannot be minimized, stored, or referenced safely.
3. Stop if the observer cannot establish source identity, timestamp, or dossier version.
4. Close the session as incomplete if minimum artifacts are unavailable; do not improvise or relabel synthetic material.
5. After exit, RP-001 remains Open unless a separate LC intake passes all gates; this plan alone never marks Complete.
