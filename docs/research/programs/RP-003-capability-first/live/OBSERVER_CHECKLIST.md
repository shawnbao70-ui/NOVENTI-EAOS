# RP-003 Observer Checklist

**Program:** Capability First  
**Preparation status:** **Open**  
**Assigned observer:** none  

Use this checklist for a real capability-mapping observation. Role labels are placeholders only; never invent an observer.

## Observer roles

- [ ] Lead observer can distinguish capability, organization unit, process, role, outcome, and permission.
- [ ] Domain representative can validate outcomes, dependencies, evidence sources, and ownership role classes.
- [ ] Comparison reviewer can assess capability-based versus department-based roadmap clarity.
- [ ] Observer understands Capability≠Permission, Cap≠Org, and Cap≠grant.

## Site / system access

- [ ] Named cohort and mapping-session access are approved for a dated window.
- [ ] Read-only source access covers process, service, outcome, portfolio, and dependency evidence in scope.
- [ ] Graph/export tools can preserve versions and source links without exposing restricted payloads.
- [ ] Participant consent and organizational confidentiality limits are recorded.

## Minimum artifacts

- [ ] Dated mapping record and enterprise scope.
- [ ] Versioned capability graph/export and glossary.
- [ ] Source-to-node/outcome trace and maturity/automation-affinity rationale.
- [ ] Roadmap comparison, disagreement/ambiguity log, falsifiers, and provenance metadata.

## Ethics / confidentiality

- [ ] Do not infer individual performance or permission from capability ownership.
- [ ] Avoid using department prestige or reporting lines as evidence of capability maturity.
- [ ] Redact personal and commercially sensitive portfolio information.
- [ ] Preserve dissenting mappings and unresolved ambiguity.
