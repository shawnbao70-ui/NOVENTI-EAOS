# RP-006 Observer Checklist

**Program:** AI Infrastructure Platform  
**Preparation status:** **Open**  
**Assigned observer:** none  

This checklist prepares a real infrastructure-readiness observation. It does not authorize scanning, configuration, deployment, or security testing.

## Observer roles

- [ ] Lead observer understands ID-01…08 and I0–I4 readiness criteria.
- [ ] Environment custodian can validate topology, identity, model/tool, observability, isolation, and approval evidence.
- [ ] Security/governance observer can review supply-chain trust, audit, tenant isolation, and access boundaries.
- [ ] OT/edge specialist is present when hybrid or plant infrastructure is in scope.

## Site / system access

- [ ] Written scope identifies the tenant/environment, systems, permitted methods, and dated window.
- [ ] Access is read-only or supervised; no active probing or configuration change is assumed.
- [ ] Sensitive topology, security, key, credential, and vulnerability material stays in controlled stores.
- [ ] Evidence handles have custodians, expiry/retention, and registrar-access arrangements.

## Minimum artifacts

- [ ] Dated, redacted topology/service inventory references.
- [ ] Completed readiness checklist/gap profile with criterion-to-source trace.
- [ ] Approval, audit/observability, isolation, and signed supply-chain records.
- [ ] Failure/degraded-mode observations where authorized, plus falsifiers and provenance metadata.

## Ethics / confidentiality

- [ ] Follow least privilege and do not expose secrets or exploitable detail.
- [ ] Report security gaps through approved channels before broad research circulation.
- [ ] Distinguish unavailable evidence from a failed control.
- [ ] Never bypass Kernel, Permission, Workflow, or AI Runtime boundaries.
