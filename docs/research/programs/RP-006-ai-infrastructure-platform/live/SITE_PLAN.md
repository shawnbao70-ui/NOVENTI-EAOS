# RP-006 Site Plan

**Program:** AI Infrastructure Platform  
**Status:** **Open** · **0 Complete**  
**Assigned observer/environment/window:** none / none / none  
**Access basis:** [SITE_ACCESS_PACK](../../../templates/SITE_ACCESS_PACK.md) · **Evidence review:** [ARTIFACT_ACCEPTANCE_RUBRIC](../../../templates/ARTIFACT_ACCEPTANCE_RUBRIC.md)

## Objective and boundary

Observe ID-01…08 readiness in a named cloud, hybrid, edge, or OT environment using read-only/supervised evidence. No scanning, configuration, deployment, or bypass is authorized.

## Target observation points

1. Identity landing and tenant isolation have traceable controls and audit sources.
2. Model/tool hosting paths preserve approval, source, version, and execution boundaries.
3. Approval bridges fail closed and do not bypass Permission/Workflow.
4. Observability links requests, models/tools, decisions, costs, and failures without secret leakage.
5. Artifact/model/tool supply chains use verifiable signing/provenance controls.
6. Edge/OT and degraded-mode behavior has explicit safety and reconnection boundaries.
7. Data/storage/memory retention and deletion align to classification.
8. Readiness gaps distinguish missing evidence from failed control.

## Required artifacts

1. Dated environment scope and redacted topology/service inventory.
2. ID-01…08/I0–I4 criterion-to-source readiness trace.
3. Identity, tenant-isolation, and access-audit evidence.
4. Model/tool registry, version, signing, and provenance evidence.
5. Approval-bridge and fail-closed workflow records.
6. Observability, incident, degraded-mode, or authorized failure evidence.
7. Data retention/deletion and cost/FinOps evidence where in scope.
8. Export IDs/hashes, gaps, falsifiers, security handling, and custodian manifest.

## Dependency systems / contexts

1. Identity provider/federation and access-audit source.
2. AI Runtime/model/tool hosting environment.
3. Artifact/model registry and signing/verification service.
4. Approval/workflow bridge evidence source.
5. Observability/logging/metrics and cost platform.
6. Edge/OT environment or controlled reference, when included.

## Access and run sequence

1. Approve exact systems, methods, accounts, window, support, security disclosure, and no-probing rule.
2. Validate read-only/supervised access and non-production/production boundaries.
3. Observe evidence and permitted exports without executing tests not pre-approved.
4. Revoke accounts, reconcile exports, and route sensitive findings through security channels.

## Risks / ethics

1. Credentials, topology, vulnerabilities, or tenant data exposure; minimize and retain controlled.
2. Observation mistaken for penetration test or operational approval; keep methods explicit.
3. Missing evidence misreported as failed control; distinguish status and confidence.
4. Active query/export affecting service or cost; pre-limit methods and volume.
5. OT/edge access creating safety/availability risk; require specialist and fail closed.
6. Infrastructure gap converted into Eng work without gates; prohibited.

## Exit conditions

1. Stop if account scope, system owner, security approval, or observation method is unclear.
2. Stop on secret exposure, suspected vulnerability, service impact, or tenant-boundary risk.
3. Stop if any action would mutate configuration, workload, workflow, or production state.
4. Return incomplete if topology/version/provenance or registrar retrieval cannot be established.
5. RP-006 remains Open; no assessment or rubric score alone marks Complete.
